# LH-007 — Routing evaluation and baseline comparison

Status: TODO
Depends on: LH-004
Owned area: evaluation CLI, task set, report generation and tests

## Scope
Build a repeatable local evaluation runner comparing rules routing with configured always-fast and always-strong baselines. Optional classifier comparison activates when LH-006 is available; it must not block this ticket.

## Definition of done
- [ ] Versioned representative general/coding/debugging/reasoning tasks have objective graders where possible and explicit human-review rubrics otherwise. Mark ungraded results honestly.
- [ ] Record exact model tags/digests where available, settings, policy, warm/cold state and available hardware metadata. Baseline identities are operator-configured, not guessed.
- [ ] Compare task success, completion time, loading overhead, tokens, errors and incomplete measurements; include classifier overhead when used.
- [ ] Repeated-run protocol documents repetitions, ordering and warmup. Machine-readable results and readable summary preserve per-task evidence and limitations.
- [ ] Fake-provider tests verify aggregation without asserting real savings. Live mode refuses missing models, never downloads them and never contacts cloud endpoints.
- [ ] Document exact live evaluation command. Harness completion is not evidence that routing beats baselines; record live evaluation as not-run if unavailable.

## Evidence required before DONE
Commands/results, changed files, report fixture provenance and known limitations. Actual live benchmark results are verified in LH-008.

## Claude Code instruction
Read README.md and docs/architecture.md. Do not gate rules evaluation on classifier work or claim a quality improvement from synthetic outputs.
