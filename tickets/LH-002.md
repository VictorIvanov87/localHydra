## Limitations and gaps (honest)
- **Upstream stop is unconfirmed.** Closing the connection is the only signal sent; no check proves Ollama's compute ended.
- **Contract helper gaps (not changed, frozen):** `validate_loopback_url` accepts ports `99999`, `abc` and `0`, and accepts `localhost` without resolving it (so `ProviderConfig`/`AppConfig` also accept them). The adapter re-validates the port and resolves/pins addresses itself. The contract has no timeout, remote-model or "partial because routing missing" distinctions: timeouts and remote models map onto existing codes (`provider_unreachable`/`stream_interrupted`/`model_unavailable`); remote models appear in `probe_models` as `unavailable`/`not_installed` plus `ModelProbe.remote_tags`; `normalize_ollama_metrics` reports `partial_final_chunk` when only `routing_ms` is missing (seen live) and `no_visible_token` for non-streamed structured calls (no ttft). A measured zero duration counts as "complete" with null throughput. A follow-up contract minor version could add a remote reason; LH-004/LH-008 should be aware.
- **Remote (cloud) model detection** relies on `remote_host`/`remote_model` in `/api/tags` (present on the tested Ollama; other versions untested) plus a conservative tag-name check (any `cloud` or `*-cloud` tag, so a local model with such a name would be refused). The verified-local cache is per provider instance and refreshed by `list_models`; a model re-created as a cloud alias in between is not noticed. Each tag costs one extra `GET /api/tags` before its first chat. The adapter cannot control traffic originated by the Ollama daemon itself.
- **Not exercised:** an https loopback target (SNI-pinning code path is untested; Ollama is plain http by default); a real connect timeout (only the httpx-error mapping is unit-tested; a loopback connect succeeds or is refused immediately); IPv6 `::1` serving (the fallback test passes with or without host IPv6 support); pre-`/api/ps` Ollama versions beyond the 404 simulation.
- `wall_ms` includes connection and cold model load; `ttft_ms` is a lower bound of client-visible time. Token budget, keep-alive/model-unload policy, retries and backoff are intentionally not implemented (runtime/routing concerns). `probe_models` is not wired into `/api/models` (LH-004). No embeddings code exists. Image inputs are not supported by `ChatMessage`.
- Not run: ruff/other linters (none configured); browser rendering (unchanged frontend); Playwright (not installed yet).

### Fixes and fails-first evidence

1. **Cancellation while suspended at a delta:** `cancel()` previously only set an event that was observed on the next iteration. A scoped cancellation watcher now closes the active response and finishes telemetry independently while the generator is suspended at either delta yield. Resumption/`aclose()` joins the watcher (cancelling it only if cancellation was not requested), so the close is not interrupted and no watcher survives cancellation or scope exit. Both `cancel()` (called twice for idempotence) and an external event are tested: receive one delta, cancel, wait 150 ms without `next`/`aclose`, then assert server-observed disconnect, zero open connections, finished telemetry and no pending adapter tasks. Subsequent iteration delivers exactly one `ChatCancelled`. **RED:** `-k without_advancing` failed both cases on the disconnect assertion before the fix. **GREEN:** both pass.
2. **Overall budget includes local-only/inventory preflight:** both chat paths now establish the absolute total deadline before `_ensure_local`; preflight is guarded by that deadline, and structured `_exchange` reuses it rather than starting a fresh budget. Discovery retains its own request bound. Tests cover both streaming and structured with 200 ms inventory / 50 ms total (must time out before any chat POST), and 150 ms inventory + 300 ms response / 400 ms total (must not reset the remaining budget). **RED:** all four cases failed before the fix (original second-pair timing: 80 ms + 80 ms / 120 ms): the first pair sent a chat request; the second pair did not raise. The second pair was later widened after a Python dev-mode run exposed a test-only scheduling flake: inventory plus debug overhead exhausted 120 ms before POST, despite correct timeout behavior. The final timing leaves 250 ms between inventory sleep and the total deadline; no production change was needed. **GREEN:** all four pass.
3. **Cumulative first-chunk budget:** streaming establishes one first-chunk deadline before opening the chat response, bounds opening by the earlier first/total deadline with the appropriate typed error, and gives the first body read only the remaining first-chunk time. Nonpositive remaining stage budgets fail without starting I/O. **RED:** 80 ms headers + 80 ms body with `first_chunk_s=0.12` incorrectly succeeded. **GREEN:** it raises `first_chunk_timeout`; existing first/idle/total timeout tests also pass.
4. **Bound complete NDJSON lines before parsing:** check the newline offset against `MAX_LINE_BYTES` before copying, stripping or decoding the line, in addition to the existing residual-buffer bound. Tests use a 128-byte limit and oversized valid JSON (200-character content), invalid JSON and whitespace, each in one HTTP chunk and split across two. **RED:** all six failed (valid/whitespace accepted, invalid data classified as `invalid_json`). **GREEN:** all six raise `malformed_response` / `line_too_long` without yielding content. An additional positive boundary test verifies that a line exactly at the limit is accepted and multiple short lines in one HTTP chunk are not incorrectly limited by aggregate chunk size.

## Terminal-yield resource remediation (second precommit repair cycle)

Status remains **IN_PROGRESS**, for parent review/closure. Root cause: both `_run()` branches yielded `ChatFinished` before their `finally` closed the response; the delta cancellation watcher had already exited. A consumer stopping on the terminal item therefore retained the open response even after method/event cancellation.

**Exact production change:** `OllamaChatStream.__anext__()` now captures the next item and, only for `ChatFinished`, awaits the underlying generator's `aclose()` before returning it. This executes the existing response/telemetry cleanup before exposing either terminal-finished branch (newline or EOF-buffer final), without setting the cancellation event or replacing the successful terminal item. Existing delta watcher, total/preflight deadline, cumulative first-chunk deadline and line-limit code are unchanged in this cycle.

**Regression added first:** `test_finished_releases_response_without_advancing_terminal_consumer`, six cases: no cancellation, repeated `stream.cancel()`, or external event after final; each with empty final content or a final that first yields a content delta. FakeOllama sends the final chunk and holds the HTTP response open. After receiving `ChatFinished`, tests wait 150 ms without advancing/closing the iterator, assert server-observed disconnect, zero open connections, finished/unchanged terminal telemetry and no pending adapter tasks, then verify further iteration stops (no second terminal). Test `finally` closes the iterator only after these assertions, including on RED failures.
