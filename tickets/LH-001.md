### Limitations (honest gaps)
- `scripts/*.sh` wrappers (install/check/contracts/smoke/dev) were **not executed** (environment required approval to run scripts, and `chmod +x` was also blocked, so use `bash scripts/<name>`). The equivalent individual commands above are the verified path; `scripts/smoke.sh` logic was reproduced manually with curl.
- The frontend shell was verified as served HTML/JS/CSS and via type checking; it was **not rendered in a browser** (browser tool permission was not granted), so the React render of live health/models data is untested. No component/UI tests exist.
- Loopback-only binding is evidenced by server logs and bind configuration (plus code/tests refusing non-loopback hosts); `lsof` was blocked and an attempt to connect via the machine's LAN IP merely timed out, which is inconclusive here. It is an application boundary, not OS-enforced isolation.
- Only `/api/health` and `/api/models` are implemented. `/api/models` does not probe Ollama (availability `unknown`); the rest of the frozen API, SQLite, generation, routing, and the Ollama adapter belong to LH-002..004. No live Ollama or model was contacted; no weights downloaded.
- Contracts are frozen by design and tests, but their fitness for real Ollama output is unproven until LH-002/LH-004 exercise them (e.g. the context estimator is a conservative heuristic, not a tokenizer; field names for Ollama raw metrics follow Ollama's documented final-chunk fields and were not checked against a live server).
- JSON Schema cannot express cross-field invariants; those are enforced by the Python reference only (marked `schema_valid` in fixtures). TS has only the sequence tracker, not the stream/lifecycle validators.
- Fixture data (tags `example/model-N:synthetic`, scores, latencies, metrics) is synthetic and not a benchmark or recommendation. Pinned versions in `backend/constraints.txt` reflect the installed set at verification time.
